# Retro Games

Barney's arcade: browser games built on Retro Kit, his shared look and game shell.

- `ARCADE.md` holds the rules for the whole arcade (every style kit and every game; Retro Kit is the first kit). Read it before any kit work or any new game. Retro Kit's own docs add to it; if the two disagree, stop and ask Barney which wins.
- For any game work, use the `retro-kit` skill (`.claude/skills/retro-kit/`) and read its `reference.md` and `design.md` before writing code.
- Layout: `kit/` is shared by every game; `games/<name>/index.html` is a game's source; `dist/<name>.html` is the built game that gets played (generated by `python kit/build.py <name>`, never edited by hand).
- The arcade website, Twisted Retro Fit, lives in `site/`: `python site/build.py` builds the listed games and the site into `_site/` (generated, not in git), and GitHub publishes it on every push to `main` (`.github/workflows/publish-site.yml`). When a new game is finished, offer to add it to `site/games.json` with a 16:9 picture of it in play at `site/art/<name>.webp`.
- Do not change `kit/` while working on a game. Changing the kit is its own job, only when Barney asks; afterwards rebuild every game (`python kit/build.py`), check `dist/kit-sampler.html` (the kit's test page) and each game, and say which games you rebuilt.
- Barney is on Windows and is learning to build software: explain what you did and why in a few plain sentences, and say clearly what you could not test.
- Git is Barney's: do not commit, push or create branches unless he asks.
