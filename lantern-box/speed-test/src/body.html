    How to run it

    1. Close any other copy of this page, including in the Claude app: two copies fight over the graphics chip.
    2. Open it in Chrome. On the phone, hold it sideways and tap Full screen first.
    3. Tap Run the test and leave it alone for about half a minute. It spends 8 seconds in each place.
    4. Copy the result line, or take a screenshot, and send it back.
    5. For a comparison, switch to Mock-up way and run it again. That's the directions page's method, with the same crowd.

    What it measures

    • Frames a second while it draws normally. A screen's own limit is usually 60.
    • A frame drawn in: for the last 2.5 seconds in each place it draws every frame eight times over, so the picture slows on purpose. Each of the eight is the next frame of play, so monsters change pose and new scenery is painted as often as in play. The gap between screen updates, divided by eight, is how long one frame takes to draw. "Under" means the device kept up with the screen even then.
    • Slowest 5% of frames: only one frame in twenty takes longer than this. Longest frame: the single worst one, usually when a new piece of scenery is painted. Hitches show up in these two.
    • Processor per frame: the share of the work the browser's own clock sees. The graphics chip's share comes on top.

    Notes

    • The targets (PRD criterion 1): on the Pixel, at least 30 fps with each frame drawn in 25 ms or less; on the computer, 60 fps. The iPhone, the HP laptop, the Fire tablet and the AMD graphics are measured and reported only.
    • The crowd and the boss only load the picture: they don't fight. The camera's rise is a starting figure, and only the kit way rises.
    • If a device falls short, add #res1 to the end of the link (ordinary sharpness) and reload.
    • A phone slows down as it warms up over minutes of play. This test shows a cool phone.
